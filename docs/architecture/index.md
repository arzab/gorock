# Что такое GOROCK

Go минималистичен. Бэкенд шаблонен. GOROCK соединяет эти две идеи — даёт стандарт там, где он нужен, и оставляет свободу там, где она важна.

Работает для любого Go-приложения: HTTP-сервер, consumer, worker, планировщик, бот.

GOROCK — это две вещи:

- **Архитектура** — где лежит код. Три слоя с чёткими правилами, одинаковые в любом проекте.
- **[gorock-kit](/gorock-kit/)** — готовый код для того, что в каждом проекте одинаковое: запуск и остановка, HTTP-сервер, загрузка конфигов, логгер, шина событий, планировщик, PostgreSQL, Redis.

Архитектуру можно использовать и без gorock-kit, но вместе они экономят больше всего: вы пишете только бизнес-логику.

→ Почему архитектура устроена именно так — [Концепты](/architecture/concepts). Сразу к делу — [Быстрый старт](/architecture/getting-started).

## Слои

GOROCK делит проект на три слоя. Каждый слой — папка в корне проекта с конкретной ответственностью.

Когда знаешь слои — знаешь, где искать любой код в любом GOROCK-проекте.

---

### Engine — `cmd/`

Запуск и оркестрация. Здесь живёт всё, что связано с тем, **как** и **какое** приложение стартует и останавливается.

```
cmd/
├── main/    — точка входа: загрузка конфигов, регистрация слоёв в движке, запуск
└── apps/    — приложения: HTTP-сервер, шина событий, планировщик и др.
```

Engine не содержит бизнес-логики — только управление жизненным циклом. Сам цикл (порядок старта, сигналы ОС, graceful shutdown) даёт [rockengine](/gorock-kit/rockengine).

---

### Realm — `internal/`

Бизнес-логика и всё уникальное для этого проекта. Здесь живёт, **что** происходит при запросе или событии.

```
internal/
├── delivery/  — что делать при HTTP-запросе, событии, задаче по расписанию;
│                самоописывающиеся сущности, которые App просто регистрирует
├── models/    — сущности предметной области
└── utils/     — вспомогательные функции, специфичные для проекта
```

`internal/` в Go — специальное слово: компилятор запрещает импортировать эти пакеты снаружи модуля.

---

### Toolkit — `pkg/`

Переиспользуемый инструментарий. Не знает о бизнес-логике — можно перенести в другой проект без изменений.

```
pkg/
├── services/  — обёртки над внешними системами: БД, кэш, внешние API
├── infra/     — примитивы самого проекта: логгер, трейсер, глобальные переменные
└── libs/      — ваш библиотечный код без состояния
```
