# Toolkit

**Toolkit** · `pkg/`

Первый шаг при создании проекта — подготовить инструментарий. До того как писать бизнес-логику, вы оборачиваете технологии, которые будете использовать.

---

## Что вы делаете на этом шаге

Вы **не реализуете бизнес-логику**. Вы создаёте обёртки над технологиями: базой данных, очередями, внешними API, кэшем — всем, что нужно проекту.

Toolkit не импортирует `internal/`. Он не знает, что такое `User` или `Task`. Он просто умеет сохранять, находить, публиковать, кэшировать. Написали один раз — переносите в любой проект без изменений.

Сервисы хранит и поднимает [rockservices](/gorock-kit/rockservices) из ядра, а большая часть типовых обёрток уже есть в [каталоге](/catalog/): PostgreSQL ([rockbun](/catalog/rockbun)), Redis ([rockredis](/catalog/rockredis)), логгер ([rocklog](/catalog/rocklog)). Ваш Toolkit тогда — тонкий слой поверх них, который описывает функционал именно вашего проекта.

---

## Services

Обёртки над внешними системами. Один сервис — одна технология: `repository`, `cache`, `storage`, `mailer`. Каждый сервис — singleton, доступен через геттер из любого слоя, а его жизненным циклом управляет движок: сервисы поднимаются раньше всех apps и закрываются после них.

→ [Services — как писать и структурировать](/architecture/services)

## Infra

Инструменты, которые нужны самому проекту, а не бизнесу: логгер, трейсер, глобальные переменные. Инициализируются первыми — логгер нужен всем уже при старте.

→ [Infra](/architecture/infra)

## Libs

Ваш собственный переиспользуемый код без состояния: хелперы, общие middleware, клиенты внешних API без соединений. Не singletons — импортируешь и используешь.

→ [Libs](/architecture/libs)
