Движок App GOROCK-проекта: HTTP-серверов, consumer'ов очередей, планировщиков, ботов. Запускает их в заданном порядке, ждёт сигнал, отмену контекста или падение App и останавливает по одному в обратном порядке. Только стандартная библиотека.

## App

```go
type App interface {
    Init(ctx context.Context) error // подготовиться: соединение, маршруты
    Exec(ctx context.Context) error // работать до отмены ctx
    Stop() []error                  // разблокировать Exec и дождаться текущей работы
}
```

- **`Exec`** при отмене `ctx` перестаёт брать новое, дообрабатывает начатое и возвращается. Всё, что он вернул после отмены, считается чистой остановкой.
- **`Stop`** вызывается сразу после отмены контекста, пока `Exec` может ещё работать. Блокирующий `Exec` (HTTP-сервер) он должен аккуратно разблокировать. Движок вызывает `Stop` не больше одного раза на каждый успешный `Init`, в том числе когда `Exec` так и не запустился — поэтому `Stop` не должен ждать `Exec`.

## Запуск

```go
// cmd/apps/apps.go
func Run(ctx context.Context, cfg Configs) error {
    engine := rockengine.New(map[string]rockengine.App{
        "bus":  rockbus.NewApp(cfg.Bus),
        "http": rockhttp.New(cfg.HTTP, httpEndpoints()...),
    })
    return engine.Run(ctx, "bus", "http") // http стартует последним и останавливается первым
}
```

```go
// cmd/main
if err := services.Init(ctx, cfg.Services); err != nil {
    return err
}
defer services.Stop()
return apps.Run(ctx, cfg.Apps)
```

## Как работает `Run`

1. **Старт:** `Init` каждого App в переданном порядке. Если один упал, уже запущенные останавливаются в обратном порядке, и `Run` возвращает ошибку с именем App.
2. **Работа:** `Exec` каждого App в своей горутине.
3. **Остановка** — по сигналу `SIGINT`/`SIGTERM`, отмене `ctx` или падению App. App останавливаются по одному в обратном порядке: отмена его контекста → `Stop` → ожидание `Exec`. Время ограничено таймаутом (30s, `WithShutdownTimeout`), ошибка называет зависший App.
4. **Результат:** причина остановки (падение App) и все ошибки `Stop` вместе. Чистая остановка — `nil`.

**Падение App** — его `Exec` вернул ошибку или запаниковал, пока его контекст не был отменён. `Exec`, вернувший `nil` до остановки, просто завершается, остальные App продолжают работать.

## Перезапуск

По умолчанию первое падение App останавливает всё, и процесс перезапускает оркестратор (Kubernetes, systemd, Docker). Если оркестратора нет:

```go
rockengine.New(apps).WithRestarts(3, time.Second) // Stop → пауза → Init → Exec, до 3 раз
```

Если перезапуски кончились или `Init` при перезапуске упал, движок останавливает всё. Переподключение к брокеру после разрыва сети лучше делать внутри самого App, в его `Exec`.

## Правила

- `New` паникует на пустом имени или nil-App, `Run` — на неизвестном или повторённом имени. Ошибки подключения видны при старте.
- Паники в `Init`, `Exec` и `Stop` превращаются в ошибки.
- Контексты App не наследуют отмену переданного `ctx` напрямую: движок отменяет их сам, по одному, в обратном порядке.
